## Pricing Formula
```
3ml  = CEILING(3 × (30ml/30 + 9),  5); if result ends in 0 → -1
5ml  = CEILING(5 × (30ml/30 + 6),  5); if result ends in 0 → -1
8ml  = CEILING(8 × (30ml/30 + 4),  5); if result ends in 0 → -1
10ml = CEILING(10 × (30ml/30 + 4), 5); if result ends in 0 → -1
20ml = CEILING(20 × (30ml/30 + 2),5); if result ends in 0 → -1
30ml = base price
```
Column order in the table: `3ml, 5ml, 7.5ml, 10ml, 20ml, 30ml` (the 7.5ml column is priced with the 8× rule above).
Rows are `6 × <td class="size-cell">`; index-based lookups use `cells[5]`/`prices[5]` for 30ml.

## Gotchas
- Cart validator expects **6** prices per product (6 size columns); `sizes` arrays in cart code are also 6 entries.
- `prodOf(id)` in the list-sheet IIFE handles both `brand|frag` pids and `data-product` slugs; `thumbOf` resolves via the `.frag-card[data-pid]` / `[data-product]` lookup and returns `''` if not found (never build a slug by hand — it 404s).
- Desktop `.filter-panel` height is clamped on open by `fitPanel()` — if you change the announce bar or header, that still self-adjusts via `host.getBoundingClientRect()`.
- **Never anchor DOM inserts on `container.querySelector('.section-heading')`** — headings now live inside wrappers (`#catalogue`, `.three-ml-section`), and `insertBefore` requires a *direct child*; a nested match throws `NotFoundError`, aborting the whole filters IIFE (silently caught as `console.warn`). `#filterResults` anchors on `#catalogue` → `:scope > .table-wrap` → `:scope > .section-heading` instead.
- `node seo-gen.js` is idempotent **and date-proof**: 3 consecutive runs are byte-identical across all 163 outputs, and a run with the clock moved to tomorrow produces byte-identical output too (verified with a preload that shifts `Date`). Dates come from `content-dates.json` (committed) — `datePublished` is fixed at `2026-09-10` per article, `dateModified` and sitemap `<lastmod>` bump only when a page's content signature changes. Never delete `content-dates.json` — that re-stamps every page with today.
- **`--make-data` brandImg round-trip:** `renderTbody` emits `imgWebp(pr.brandImg)` (`.webp`) but `--make-data` parsed that `src` straight back into `products.json.brandImg` — every run then flipped 152 brand logos png→webp (and regenerated 155 fragrance pages + articles + content-dates; broken at HEAD too). Fixed in seo-gen.js by normalising `.webp → .png` when reading brandImg back. Round-trip is now byte-stable — verify with before/after SHA256 of `products.json`+`index.html`+`content-dates.json` around `node seo-gen.js --make-data`.
- **The CRLF trap:** `core.autocrlf=true`, so every `git checkout` rewrites `index.html` with CRLF. seo-gen therefore normalises `CRLF → LF` on read (`let s = fs.readFileSync(IDX,'utf8').replace(/\r\n/g,'\n')`). Without that, the two `=== '\n'` newline-consumption checks — `:572` (`obEnd`, ItemList) and `:646` (`stripMarks`, FAQ/ARTICLES) — see `'\r'`, skip, and leave a line behind while insertion still adds one: **+4 blank lines in `index.html` on the first run after any checkout**. A plain idempotency loop never catches this, because it runs seo-gen first so run2/run3 both see LF output. To test: force CRLF into `index.html`, run twice, expect an empty `git diff --numstat -- index.html`. If stray blanks do appear, `git checkout -- index.html` rather than hand-stripping them.
